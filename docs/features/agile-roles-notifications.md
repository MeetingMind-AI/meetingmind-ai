# Agile Team Roles & Tailored Notification Profiles

## 1. Overview & Problem Statement

Modern software teams run different Agile ceremonies—daily standups, sprint plannings, backlog grooming, and architectural reviews. In these meetings, participants have distinct responsibilities:
- **Scrum Masters** need immediate alerts for impediments, schedule requests, parked topics, and process blockers.
- **Product Managers** track scope changes, user stories, customer impact, and roadmap alignment.
- **Team Members (Developers & Designers)** require deep focus; constant popups and audio chimes for general meeting logistics cause cognitive overload and alert fatigue.

**MeetingMind AI** implements an intelligent **Agile Role-Based Notification Architecture**. Team members are assigned distinct agile personas with customizable notification preference profiles that govern how real-time micro-summaries, proposals, and audio chimes are delivered during live meetings.

---

## 2. Supported Agile Team Roles

Team roles are tracked in the PostgreSQL `team_memberships` table (`backend/app/db/models.py`) under the `role` column:

| Agile Role | System Identifier | Focus Areas & Operational Responsibilities |
|---|---|---|
| **Scrum Master** | `scrum_master` | Process health, removing impediments, tracking parking lot topics, scheduling syncs, and unblocking sprint deliverables. |
| **Product Manager** | `product_manager` | Business requirements, user story validation, scope boundaries, roadmap milestones, and strategic insights. |
| **Team Member** | `team_member` | Core engineering execution, technical architecture, bug fixes, code implementation, and direct task commitments. |

> **Backward Compatibility**: Legacy roles (`admin`, `owner`, `member`) automatically map to their agile equivalents: `admin` -> `scrum_master`, `member` -> `team_member`.

## 3. Notification Preference Profiles & Tag Taxonomy

Each member's notification configuration is stored as a JSONB array in `team_memberships.notification_preferences`.

### 3.1 Default Role Profiles

When a user joins a team or is assigned a role, the system applies standard role-tailored defaults (`backend/app/api/teams.py`):

```python
DEFAULT_ROLE_PREFERENCES = {
    "scrum_master": [
        "type:blocker",
        "type:parking_lot",
        "type:to_schedule",
        "type:to_do",
        "type:insight",
    ],
    "product_manager": [
        "type:insight",
        "type:to_do",
        "business",
    ],
    "team_member": [
        "type:to_do",
        "technical",
    ],
}
```

### 3.2 Notification Preference Taxonomy
- **Type Keys (`type:<action_type>`)**:
  - `type:blocker`: Urgent hurdles or technical blockers requiring escalation.
  - `type:parking_lot`: Deferred discussions moved offline.
  - `type:to_schedule`: Calls, demos, or syncs requiring calendar scheduling.
  - `type:to_do`: Actionable work deliverables and implementation tasks.
  - `type:insight`: Real-time architectural or business takeaways detected by AI.
- **Category & Topic Tags**:
  - `business`, `scope`, `feature`: Product and roadmap-related proposals.
  - `technical`, `architecture`: Engineering and codebase-focused proposals.
  - Custom team topics created via `POST /api/teams/{id}/topics` (e.g., `#security`, `#devops`).

## 4. Real-Time Proposal & Alert Filtering Engine (`Live.jsx`)

During a live meeting, real-time micro-proposals generated by the Scrum Master persona stream over WebSockets (`WS /api/ws/ingest/{meeting_id}`). The frontend evaluation engine (`frontend/src/pages/Live.jsx`) determines whether an intrusive toast notification and audio chime should trigger:

```
                  Live Micro-Proposal / Insight Received
                                    │
                                    ▼
                    Is User Directly Assigned to Task?
                     (assignee_id == user.id OR name match)
                                    │
                    ┌───────────────┴───────────────┐
                   YES                              NO
                    │                               │
                    ▼                               ▼
            [ TRIGGER ALERT ]         Is Event Type Suppressed
             (Toast + Chime)         in notification_preferences?
                                                    │
                                    ┌───────────────┴───────────────┐
                                   YES                              NO
                                    │                               │
                                    ▼                               ▼
                             [ SILENT DROP ]               Evaluate Role Profile:
                                                           • Scrum Master:
                                                             Alert on all operational
                                                             proposals (to_do, parking_lot,
                                                             to_schedule, blocker).
                                                           • Product Manager:
                                                             Alert on insights, business
                                                             tags, scope changes.
                                                           • Team Member:
                                                             Remain silent (avoid fatigue).
```

### 4.1 Direct Task Assignment Priority
If an action item proposal explicitly assigns the authenticated user (via `assignee_id` foreign key, or natural-language name extraction in the task content), the alert **always fires**, ensuring developers never miss assigned work regardless of their general notification filter settings.

### 4.2 Scrum Master Notification Experience
Scrum Masters and meeting hosts receive comprehensive alerts across all operational categories. When a participant mentions:
> *"Let's park this database migration debate for next sprint"*

The Scrum Master receives an immediate toast card with one-click **"Accept"** / **"Reject"** buttons to file it to the Kanban parking lot immediately.

### 4.3 Product Manager Notification Experience
Product Managers are alerted when discussions drift into feature commitments or user-facing changes:
> *"We need to adjust the export flow to support multi-tenant CSV downloads"*

The PM receives an alert tagged with `#business`, enabling immediate review of scope creep before commitments are finalized.

### 4.4 Team Member (Developer) Focus Experience
Team members experience a quiet, low-interruption environment. Speech-to-text transcript lines stream passively, but intrusive toasts and chimes are withheld unless:
1. The developer is explicitly tagged or assigned a task.
2. The proposal matches an explicitly subscribed custom tag (e.g., `#infrastructure`).

## 5. REST API Endpoints

### 5.1 List Team Members & Notification Profiles
```http
GET /api/teams/{team_id}/members
```
Response:
```json
{
  "members": [
    {
      "id": 12,
      "name": "Alex Miller",
      "email": "alex@company.internal",
      "role": "scrum_master",
      "notification_preferences": [
        "type:blocker",
        "type:parking_lot",
        "type:to_schedule",
        "type:to_do",
        "type:insight"
      ]
    },
    {
      "id": 14,
      "name": "Maria Chen",
      "email": "maria@company.internal",
      "role": "team_member",
      "notification_preferences": [
        "type:to_do",
        "technical"
      ]
    }
  ]
}
```

### 5.2 Update Member Role & Notification Preferences
```http
PATCH /api/teams/{team_id}/members/{user_id}
Content-Type: application/json

{
  "role": "product_manager",
  "notification_preferences": [
    "type:insight",
    "type:to_do",
    "business",
    "scope"
  ]
}
```
Requires workspace owner/admin permissions, or user updating their own profile.

## 6. UI Configuration Workflow

1. **Initial Team Setup (`TeamSetupModal.jsx`)**:
   - When creating or joining a team, the user selects their primary Agile role (`Scrum Master`, `Product Manager`, `Team Member`).
   - The corresponding default notification profile is automatically initialized.

2. **Team Settings Management (`Settings.jsx`)**:
   - Navigate to **Settings -> Team Management**.
   - View all team members in a structured table with avatar photos and role badges.
   - Team owners can modify roles via dropdown.
   - Individual members can expand their **Notification Filters** card to toggle specific event types (Blockers, Parking Lot, Tasks, Insights) and topic badges with real-time saving.
